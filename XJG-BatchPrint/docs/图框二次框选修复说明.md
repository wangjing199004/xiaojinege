# 图框第二次框选异常修复（2026-10-15）

## 代码检查结果

修改的是根目录 src 下的优化版，batchPrintZWCAD-main 保留为原始对照。

1. 原版 FieldBoxSelectDialog.cs 中，StartUserInteraction 创建的 EditorUserInteraction 只 End() 后置空，没有显式 Dispose。该类型实现 IDisposable。优化版则完全绕过该作用域，使用 Hide、DoEvents、PushFrame 和焦点抢占模拟交互。两条路径均改为宿主管理的模态窗口以及成对创建/Dispose 的交互作用域（AutoCAD）。ZWCAD 保留隐藏/恢复窗口的兼容分支，不再使用插件自建的等待循环。
2. CadWindowFocus.ResolveCadMainWindow 找到无属主的 AfxWnd 主窗口后直接停止枚举，却没有把该窗口保存到返回值，结果可能返回之前枚举到的其它窗口或退回 MainWindowHandle。已补上保存句柄。
3. TransientFrameMarkers 把 subDrawingMode 当成独占的分组编号，使用 EraseTransients 批量清除；实际该绘制顺序是宿主共享状态。已改成逐实体 EraseTransient，避免干扰其它覆盖层。
4. 原优化版在框选期间修改 OSMODE 的几何中心位。现在不再修改捕捉设置，而是取点前撤下辅助红框、取点后恢复；让用户可以捕捉实际图框上的端点和交点。

这些是代码级缺陷和交互风险；当前没有运行中的 CAD 或用户复现图纸，尚不能把某一项认定为实机故障的唯一根因，也不能声称已完成实机回归。

## 修改位置

- src/Common/Commands/BatchPlotCommands.cs：字段窗口改用 CAD ShowModalWindow，删除手动等待消息循环。
- src/Common/Commands/AddTitleBlockCommands.cs、EditTitleBlockCommands.cs：新增与编辑共用新入口。
- src/Common/Views/FieldBoxSelectDialog.xaml.cs：交互作用域、异常收尾、取消后恢复；不再接管 OSMODE。
- src/Common/Infrastructure/CadWindowFocus.cs：主窗口句柄返回错误。
- src/Common/Infrastructure/TransientFrameMarkers.cs：逐实体清理与取点期间暂停标识。

字段窗口打开时为模态；需要操作图面时先点击对应“框选”按钮，取点期间可缩放和平移。

对应项目均使用 Release 编译。请保留各目录内的依赖文件，不要仅复制主 DLL。关闭并重新启动 CAD 后 NETLOAD 对应平台的新 DLL，同一个 CAD 进程不要混载旧版与修复版。

## 实机复验步骤

1. 在原复现图纸中启用端点、交点捕捉，记录当前 OSMODE。
2. 图框库→新增第一个图框，连续框选图名、图号并确定。
3. 不重载插件，新增第二、第三个不同图框，每次完成图名、图号和外框框选。
4. 第一次取点及第二个角点时分别按 Esc 取消，然后重新框选。
5. 取消整窗后再次新增；再试编辑已有图框→确定→新增下一图框。
6. 确认角点跟随光标、能捕捉实际块内端点/交点、临时红框在确定/取消后清除、OSMODE 与开始一致。
7. 另测试命令行 ZBP_ADD_TITLE_BLOCK 入口，以及预先有批量打印序号覆盖层时的框选与清理。
